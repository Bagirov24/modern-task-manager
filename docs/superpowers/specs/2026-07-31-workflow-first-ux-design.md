# Modern Task Manager: Workflow-first UX Design

Дата: 2026-07-31  
Статус: согласованный дизайн, ожидает финального ревью пользователя

## 1. Цель

Modern Task Manager должен стать спокойным рабочим пространством менеджера проекта. За первые 10 секунд пользователь должен понимать:

1. Какое действие выполнить сейчас.
2. Что он обязан сделать сегодня.
3. От кого ожидается ответ и что сделать после него.
4. Какие задачи и проекты требуют вмешательства.
5. Где находится подтвержденный контекст: требования, решения, документы, переписка и рабочие инструменты.

Главный UX-принцип:

> Интерфейс организуется вокруг обязательств и следующих действий, а не вокруг типов сущностей и количества функций.

## 2. Согласованные продуктовые решения

| Решение | Выбранный вариант |
|---|---|
| Режим главного экрана | Смешанный: личные действия сверху, команда и проекты ниже |
| Focus Now | Гибридный: система предлагает, пользователь может закрепить другую задачу |
| Личный рабочий список | Единый список задач, ответов, follow-up и согласований |
| Визуальная плотность | Сбалансированная: компактные строки, воздух вокруг ключевых действий |
| Глубина изменения | Workflow-first UX без переписывания приложения с нуля |
| Настраиваемость | Можно скрывать второстепенные блоки, но нет произвольного конструктора Dashboard |

## 3. Текущие проблемы

| Область | Текущее состояние | UX-проблема | Целевое изменение |
|---|---|---|---|
| Навигация | Все разделы выглядят равноправным списком | Пользователь не понимает, где ежедневная работа, а где справочники | Сгруппировать пункты по намерению: моя работа, планирование, знания, управление |
| Dashboard | Много последовательных секций | Focus Now, ссылки, задачи, календарь, внимание и проекты конкурируют | Выстроить строгую иерархию: Focus Now, мои действия, ожидания, командный радар |
| Задачи | Несколько представлений имеют разную плотность и метаданные | Контекст теряется между List, Board, Calendar и Timeline | Единый каркас страницы и общий task drawer |
| Task drawer | Контекст разбит между полями и вкладками | Следующее действие, ответственность и три срока не доминируют | Закрепленная верхняя часть и отдельный блок следующего действия |
| Проекты | Карточки удобны для обзора одного проекта | Сложно сравнить health, milestones и причины риска | Компактная сравнительная таблица и объяснимый health |
| Action Inbox | Статусы существуют, но требуют более ясной иерархии | Канал сообщения может доминировать над требуемым решением | Группировка по действию: ответить, уточнить, ждать, FYI |
| Требования и документы | Режимы используют общую модель | Пользователь может воспринимать их как дубликаты | Knowledge Hub для поиска и связей, Documents для авторинга и версий |
| Полезные ссылки | Каталог самостоятельный | Может потеряться связь с рабочим контекстом | Показывать ссылки в задачах и проектах, сохраняя простой каталог |
| Отчеты | Счетчики могут повторять Dashboard | Неясно, зачем переходить в отчет | Отчеты показывают тренды, причины и сравнение периодов |
| Настройки | Параметры разных уровней могут смешиваться | Сложно оценить влияние и безопасность изменения | Разделить личные, workspace, интеграционные и security-настройки |

## 4. Информационная архитектура

### 4.1 Desktop sidebar

**Моя работа**

- Обзор / My Work
- Входящие действия
- Мои задачи

**Планирование**

- Проекты
- Доски
- Календарь

**Знания**

- Требования и знания
- Документы
- Полезные ссылки

**Управление**

- Отчеты
- Настройки

В нижней части:

- Быстрый поиск `Ctrl/Cmd + K`
- Профиль пользователя

### 4.2 Global header

Header содержит только глобальные действия:

- Breadcrumb текущего контекста.
- Глобальный поиск.
- Уведомления.
- Переключатель темы.
- Единая кнопка «Создать».

Меню «Создать» включает задачу, входящее действие, документ, проект и полезную ссылку. Контекстные действия остаются внутри страницы.

### 4.3 Mobile navigation

Нижняя навигация:

- Обзор
- Входящие
- Задачи
- Проекты
- Еще

Task drawer становится полноэкранным view. Вторичные столбцы таблиц превращаются в метаданные строки, а не просто исчезают.

## 5. Dashboard / My Work

Порядок блоков фиксирован по приоритету внимания.

### 5.1 Focus Now

Показывает одну задачу или действие:

- Название и проект.
- Статус и приоритет с текстом.
- Финальный срок и оценку.
- Следующее действие и его срок.
- Причину блокировки, если есть.
- Кнопки «Начать», «Открыть», «Завершить», «Заблокировать», «Сменить».

Система предлагает Focus Now по объяснимой формуле:

1. Закрепленная пользователем задача.
2. Активная задача со статусом `in_progress`.
3. Просроченное личное действие.
4. P0/P1 с ближайшим `next_action_due_at`.
5. Задача с ближайшим `final_due_at`.

Интерфейс помечает источник выбора: «Закреплено вами» или «Предложено системой».

### 5.2 Мои действия

Единый список обязательств объединяет:

- Задачи.
- Ответы на коммуникации.
- Follow-up.
- Согласования.
- Решения, ожидающие менеджера.

Каждая строка показывает:

- Checkbox или команду завершения.
- Маркер источника.
- Название и проект.
- Тип обязательства.
- Владельца следующего действия.
- Срок следующего действия.
- Статус риска или блокировки.

Переключатели: «Сейчас», «Сегодня», «Неделя». Сортировка использует просрочку, критичность, срок и риск. Источник не влияет на приоритет.

### 5.3 Жду ответа

Ожидания не смешиваются с активными действиями. Строка показывает:

- От кого ожидается ответ.
- Что именно ожидается.
- Response SLA.
- Просрочку.
- Что сделать после ответа.
- Когда отправить напоминание.

### 5.4 Команда и проекты

Радар расположен ниже личного рабочего контура и показывает только исключения:

- Просрочки.
- Блокеры.
- Обязательства без следующего действия.
- Перегрузку.
- Проекты `At risk` и `Off track`.

Dashboard не заменяет Reports и не содержит тяжелую аналитику.

## 6. Задачи и рабочие представления

### 6.1 Общий каркас

Все представления используют одинаковый page shell:

1. Заголовок и основное действие.
2. Переключатели `List / Board / Calendar / Timeline`.
3. Saved views.
4. Поиск и активные фильтры.
5. Рабочая область.
6. Task drawer.

Последнее представление сохраняется для пользователя.

### 6.2 List

- Строки высотой 48-52 px.
- Видимые активные фильтры в виде удаляемых chips.
- Настройка столбцов без горизонтального хаоса по умолчанию.
- Bulk-панель появляется только после выбора строк.
- Дефолтные столбцы: priority, title, project, status, assignee, final due, next action due.
- Комментарии, документы, зависимости и блокировка отображаются компактными счетчиками и маркерами.

### 6.3 Board

- Колонки отражают workflow проекта.
- `Blocked` остается признаком поверх статуса.
- Колонки показывают количество задач и WIP-сигнал.
- Название карточки занимает не более двух строк.
- На карточке остаются только priority, title, assignee, due, block, docs и subtask progress.
- Остальной контекст доступен в drawer.

### 6.4 Calendar

- Неделя является основным рабочим масштабом.
- Month используется для общего планирования.
- `final_due_at`, `response_due_at` и `next_action_due_at` имеют разные текстовые маркеры и иконки.
- День показывает нагрузку и предупреждает о перегрузке.
- Перенос даты требует подтверждения, если меняется финальный срок.

### 6.5 Timeline

- Показывает milestones, диапазоны и зависимости.
- Задачи без дат не занимают фиктивное место на timeline.
- Блокирующая связь видна текстом и линией.
- Изменение диапазона не меняет зависимости автоматически.

## 7. Task drawer

На desktop drawer открывается справа и сохраняет исходный список или доску. На mobile используется fullscreen.

### 7.1 Закрепленная верхняя часть

- Project path.
- Название.
- Workflow status.
- Priority.
- Task type.
- Final due.
- Кнопка краткого статуса.

### 7.2 Вкладки

- Обзор
- Документы
- Коммуникации
- Тестирование
- Активность

### 7.3 Обзор

Первым отображается блок «Следующее действие»:

- Описание.
- Владелец.
- Срок.

Далее:

- Менеджер конечного результата.
- Текущий исполнитель.
- От кого ждем.
- Response due.
- Действие после ответа.
- Risk level и причина.
- Контекст.
- Ожидаемый результат.
- Acceptance criteria.
- Связанные задачи и материалы.

Footer содержит только команды, доступные в текущем состоянии.

## 8. Проекты

### 8.1 Каталог

Основной режим - компактная таблица сравнения:

- Название.
- Health с текстом и иконкой.
- Прогресс.
- Ближайший milestone.
- Просрочки и блокеры.
- Краткая причина риска.
- Рекомендуемое действие.

Карточный режим не используется по умолчанию, поскольку затрудняет сравнение проектов.

### 8.2 Project detail

Вкладки:

- Обзор
- Задачи
- Milestones
- Команда
- Документы
- Активность

Обзор отвечает на четыре вопроса:

1. Каково текущее состояние проекта.
2. Почему health имеет такое значение.
3. Какой milestone ближайший.
4. Какое действие должен выполнить менеджер.

Health рассчитывается объяснимыми правилами. Рядом всегда отображаются причина и затронутые обязательства.

## 9. Action Inbox

Action Inbox является очередью решений, а не мессенджером.

Группы:

- Новые.
- Нужно ответить мне.
- Спросить заказчика.
- Уточнить у команды.
- Жду ответа.
- Готово к ответу.
- FYI.
- Закрыто.

Карточка показывает источник, отправителя и роль, subject, preview, проект, связанную задачу, срок и статус действия.

Detail panel содержит:

- Ссылку на исходное сообщение.
- Рабочий preview.
- Следующее действие.
- Владельца и срок.
- Связанную задачу и материалы.
- Подтвержденный AI-черновик, если доступен.

Полный разговор открывается в исходной системе. Отправка черновика всегда требует явного подтверждения.

## 10. Требования, знания и документы

### 10.1 Требования и знания

Knowledge Hub оптимизирован для поиска и проверки контекста:

- Полнотекстовый поиск.
- Фильтры проекта, типа, статуса и уровня подтверждения.
- Path `workspace -> project -> task/document`.
- Краткий фрагмент совпадения.
- Автор, версия и дата последней проверки.
- Связанные задачи, документы, коммуникации и решения.

Статус знания:

- Подтверждено.
- Требует проверки.
- Устарело.
- Открытый вопрос.

Открытый вопрос имеет владельца, срок уточнения и связанное действие.

### 10.2 Documents

Documents остается режимом авторинга:

- Markdown editor.
- Version history.
- Restore.
- Attachments.
- Permissions.
- Confidentiality.
- Связи с task, project, requirement и communication.

Просмотр и редактирование разделены, чтобы большой редактор не мешал поиску знания.

### 10.3 Полезные ссылки

Каталог остается простым:

- Название и назначение.
- Project или «Общее».
- Category и environment.
- Login.
- Access status и access hint.
- Notes.
- Favorite.
- Open.

Пароли и секреты не сохраняются. Контекстные ссылки отображаются внутри task drawer и project detail.

## 11. Reports

Reports не повторяет счетчики Dashboard. Раздел показывает:

- Изменение выполнения в срок.
- Cycle time.
- Количество и динамику просрочек.
- Время ожидания ответа.
- Причины риска.
- Сравнение проектов и периодов.
- Проверяемый управленческий вывод.

Экспорт статуса включает выполненное, текущие риски, ожидания, следующий шаг и открытые вопросы.

## 12. Settings и Profile

Settings разделены на:

- Общие.
- Workflow.
- Уведомления.
- Интеграции.
- Безопасность.
- AI.

Личные настройки отделены от workspace-настроек. Опасные изменения показывают scope влияния и требуют подтверждения.

Profile содержит только идентичность, роль, часовой пояс, рабочие часы и параметры безопасности.

## 13. Визуальная система

### 13.1 Плотность и геометрия

- Строки: 48-52 px.
- Touch target: минимум 44 x 44 px.
- Внутренние отступы панелей: 12-16 px.
- Скругления: 8-10 px.
- Карточки применяются только для самостоятельных объектов.
- Страница и секции не оформляются как вложенные карточки.

### 13.2 Цвет

- Нейтральные поверхности являются основой.
- Primary используется для действия, выбора и focus ring.
- Success, warning и danger используются только для фактических сигналов.
- Статус всегда содержит текст и иконку; цвет является дополнительным каналом.

### 13.3 Typography

- Один H1 на страницу.
- H2 секций компактный и не конкурирует с данными.
- В таблицах и панелях используются небольшие заголовки без hero-scale typography.
- Letter spacing равен нулю, кроме коротких uppercase labels.

## 14. Состояния и доступность

### Loading

Skeleton сохраняет размеры будущего контента. Динамические значения не должны сдвигать layout.

### Empty

Empty state объясняет, почему данных нет, и предлагает одно следующее действие. Он не содержит маркетингового описания функции.

### Error

Ошибка содержит:

- Что не удалось.
- Сохранились ли введенные данные.
- Как повторить действие или восстановиться.

### Success

Короткий snackbar подтверждает действие. Для необратимых операций отображается undo, если это возможно.

### Keyboard и screen reader

- `Ctrl/Cmd + K`: поиск.
- `C`: быстрое создание.
- `/`: фокус поиска или фильтра текущего списка.
- `Esc`: закрытие drawer или modal.
- Стрелки: навигация по спискам и меню.
- Все icon buttons имеют `aria-label` и tooltip.
- Focus ring видим во всех темах.
- Контраст соответствует WCAG AA.

## 15. Компонентные границы

Дизайн реализуется расширением существующих компонентов.

| Компонент | Ответственность |
|---|---|
| `AppShell` | Sidebar, header, mobile navigation и responsive layout |
| `PageHeader` | Breadcrumb, title, summary и page actions |
| `ViewSwitcher` | List, Board, Calendar, Timeline и сохранение последнего view |
| `FilterBar` | Поиск, filters, saved views и активные filter chips |
| `ActionRow` | Общая визуальная модель задачи, ответа, follow-up и approval |
| `TaskDrawer` | Контекст задачи и вкладки, независимо от исходного представления |
| `StatusBadge` | Иконка, текст и цвет статуса |
| `DeadlineIndicator` | Тип срока, значение, просрочка и tooltip |
| `AttentionState` | Loading, empty, error и retry без изменения размеров layout |

Каждый компонент получает данные через существующие hooks/API и не создает параллельный store.

## 16. Потоки данных и взаимодействия

### Единая очередь действий

Frontend нормализует задачи и communication items в read model `ActionItem`. Исходные сущности остаются отдельными; команды направляются в их существующие API.

### Открытие task drawer

URL хранит `task` query parameter. Обновление задачи инвалидирует task, list, Dashboard и project health queries, но не сбрасывает filters и scroll position.

### Focus Now

Backend или selector возвращает кандидата и объяснение выбора. Пользовательское закрепление имеет приоритет и хранится как preference, а не новый task status.

### Project health

Health состоит из значения, причин и recommended action. UI не пытается восстановить причины только по цвету.

## 17. Безопасность

- Sensitive Data Guard применяется до сохранения текста.
- Ошибка не отражает найденный секрет обратно пользователю.
- Restricted content не попадает в глобальный preview без проверки прав.
- External links открываются с `target="_blank"` и `rel="noopener noreferrer"`.
- AI получает только разрешенный и очищенный контекст.
- AI не отправляет сообщение и не изменяет обязательства без подтверждения.

## 18. Критерии UX-проверки

1. Пользователь за 10 секунд называет Focus Now, три главных действия и два просроченных ожидания.
2. Открытие и закрытие задачи сохраняет view, filters и scroll position.
3. Новая задача создается с любой основной страницы клавишей `C`.
4. Входящее сообщение разбирается максимум за два решения после открытия.
5. Причина `At risk` доступна без перехода в Reports.
6. Источник требования находится максимум за два перехода.
7. Статусы понятны в монохромном режиме.
8. Основные сценарии выполняются только с клавиатуры.
9. Mobile UI не требует горизонтального скролла для ежедневной работы.
10. Loading, empty и error states не изменяют геометрию основного layout.

## 19. Проверка реализации

### Unit

- Focus Now ranking и pin override.
- Нормализация разных сущностей в `ActionItem`.
- DeadlineIndicator для трех типов сроков.
- Project health labels и reasons.
- Saved view persistence.

### Component

- Filter chips и reset.
- Task drawer tabs и focus management.
- StatusBadge без зависимости только от цвета.
- Empty, loading, error и retry.
- Mobile bottom navigation.

### E2E

- Dashboard -> действие -> task drawer -> update -> возврат с сохраненным контекстом.
- Inbox -> связать с задачей -> подготовить draft -> подтвердить.
- Projects -> открыть risk reason -> recommended action.
- Knowledge search -> source document -> связанная задача.
- Keyboard-only создание и обновление задачи.
